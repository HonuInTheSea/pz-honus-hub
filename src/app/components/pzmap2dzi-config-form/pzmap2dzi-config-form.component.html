How the Rust map job works

These notes explain which settings affect work, storage, and memory.

Build stages

Deploy writes the viewer, scan reads map headers, textures indexes and caches packs, then the renderer creates base isometric tiles, top-view tiles, overlays, saves, and each Additional map. The live log reports each texture pack and plant-texture step.

Coverage controls

DZI cell range sets the image boundary. Render cell range limits the cells that receive tiles. A range such as all_mod_maps includes configured Additional maps; explicit rectangles reduce work most.

Reference resources

The upstream notes use 32 GB RAM and 500 GB free space as an isometric baseline, with 1 TB recommended. Planning memory is about 500 MB per worker plus 4 GB shared for isometric rendering.

Overlays and cache

Zombie and foraging raster tiles use the selected logical CPU core count and skip full-size allocations for transparent tiles. The cache limit controls decoded texture-page RAM; larger tiles require more RAM per worker. GPU mode is limited to the pyramid compositing/downsample step; image codecs and disk output remain native CPU work.

Estimates combine the upstream B42.6 performance table, the complete local Ultra output calibration, and prior completed, stopped, or errored runs when available. Actual results vary with map coverage, save size, CPU, storage, and whether source tiles are already cached.
